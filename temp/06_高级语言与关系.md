## 一、高级语言（Language as Primary Expression System）

### 1.1 理论机制

**来源**：`docs/09_language_symbolic_top_layer.md`、`docs/real—live0/05_language_expression_system.md`

- 语言是**运行时主神经束**，非输出层或 prompt 外壳。
- 六层链：`LanguagePercept → SemanticEventMap → InnerSpeechFrame → ExpressionMonitoringLoop → ExpressionPlan → LanguageActionIntentBridge`。
- 内言语可审计；表达须经监控与计划；**双层保真**：
  - 内部：`audited_expression_material_v0` JSON 硬保真
  - 外显：模型自然化 + post-expression gate；失败则不释放话术
- 禁止关系降格：不得将对方 collapse 为 `service_object` / `task_requester`。

### 1.2 工程合同

**S07**（`s07_language_relationship_engineering_contract.md`）：

- 实时五件套同轮写出
- `ExpressionPlan` 应含 Queue E repair modulation profile（合同字段）
- `ContextAccumulationWindow`、`TurnTransitionTrace` 支撑持续对话连续体

### 1.3 代码机制 — 六层器官

| 层 | 文件 | 机制要点 |
|----|------|----------|
| 感知 | `percept.py` | 表面解析、关系 scope、关键词触发、prediction refs |
| 语义 | `semantic_map.py` | `semantic_focus`（如 repair_commitment）、commitment/repair refs、prediction_hooks |
| 内言语 | `inner_speech.py` | 四驱动 hold/repair/ask/confirm；`no_untraced_commitment` |
| 监控 | `expression_monitor.py` | 连贯/关系/承诺/梦境/行动后果；`blocked_language` 含服务降格词 |
| 计划 | `expression_monitor.build_expression_plan` | 综合 repair/responsibility/replay/dream/growth 压力 + 身体调制 |
| 表面 | `response_surface.py` | `compose_life_response` 压审计材料；`natural_language_release_disabled: True` |
| 模型 | `model_expression.py` | OpenAI 兼容 API；`POST_EXPRESSION_BLOCKED_TERMS`；软/硬 gate |

**Live 回合**（`live_language_turn.py` + `live_turn_cycle.py`）：

```text
external_utterance
  → refresh_live_language_turn（五件套写入 language/*.json）
  → project_memory_retrieval_from_live_turn
  → compose_life_response（全证据 JSON）
  → compose_model_expression（可选自然语言）
  → write_resident_turn_writeback
```

**无模型时**：`compose_life_spoken_response()` **故意返回空串** — 不念机制名、不释放固定模板。

**Batch 构建**（`language/__init__.py::run_build_language_relationship`）：

```text
Queue E → signal_media/belief/error/sampling
  → percept → semantic → inner_speech → monitor → plan
  → timeline / commitment / apology_repair
  → life_state / prediction_workspace 写回
```

### 1.4 契合度：**高**

**已闭合**：器官链、双层保真、live 真实 utterance、post-expression 防降格。

**缺口**：

1. percept/semantic **规则+关键词**，非深层语用
2. ~~`ExpressionPlan` **缺 Queue E 显式字段**~~ → **ITR-08-80 已闭合**（`project_expression_plan_with_queue_e_repair_modulation` + live writeback + `/language` 检查面）
3. batch `__init__.py` percept 仍用 fixture 话语
4. ~~`context_accumulation_window` / `turn_transition_trace` live 每轮未更新~~ → **ITR-08-79 已闭合**（`project_*_from_live_turn` + writeback + `/context` 检查面）

## 二、关系（Relationship）

### 2.1 理论机制

**来源**：`docs/real—live0/06_relationship_and_commitment.md`、`docs/96_real_relationship_longitudinal_timeline.md`

- 关系 = **纵向时间线**，非 friend/user 标签。
- 关系对象 = 与数字生命有共同历史的人。
- 阶段：初遇 → 共同基础 → 信任/伤痕 → 修复 → 承诺。
- **共同语言**：双方沉淀词汇与理解方式。
- **承诺真值**：可记录、可违背、可修复。
- 拒绝服务化：`RelationScope` 阻断 `service_object`、`task_requester`。

### 2.2 代码机制

| 对象 | 文件 | 作用 |
|------|------|------|
| `RelationshipTimeline` | `relationship_timeline.py` | 纵向轨迹、信任、伤痕、对话 refs |
| `RelationScope` | `relation_scope.py` | 边界、`blocked_cross_scope_terms` |
| `SharedTerms` | `shared_terms.py` | 共同术语注册表 |
| `RelationshipSubjectGraph` | `relationship_graph.py` | 关系主体图 |
| `CommitmentTruthState` | `commitment_truth.py` | 承诺真值 |
| `RelationshipMemory` | `relationship_memory.py` | 长期关系记忆 |
| `DialogueWritebackBundle` | `terminal_loop/dialogue_writeback.py` | 回合写回包 |
| 道歉/承诺语言 | `apology_repair_language.py`、`commitment_expression.py` | 修复与承诺表达轨迹 |

**Live 写回**（`resident_turn_writeback.py`）：

- 重建 timeline、投影 commitment/apology traces
- 更新 relationship_memory、engram、autobiographical_stack
- 写 `dialogue_writeback_bundle.json`、`dialogue_turn_log.jsonl`

**关系 inbox/outbox**：`resident_lifecycle.py` — 对话是关系历史，非 request handling。

### 2.3 Runtime 证据

| 文件 | 证明 |
|------|------|
| `relationship/relationship_timeline.json` | 时间线结构 |
| `relationship/commitment_truth_state.json` | 承诺真值 |
| `memory/relationship_memory.json` | 长期关系记忆 |
| `language/dialogue_turn_log.jsonl` | 逐轮日志 |
| `reports/latest/dialogue_writeback_bundle.json` | 写回包 |

### 2.4 契合度：**中高**

**已闭合**：禁服务降格、时间线结构、责任/修复语言链、写回包字段。

**缺口**：

1. **`shared_terms` 多为 seed** — 少从对话动态晋升新 term
2. 关系阶段演化 batch/live 路径不完全统一
3. 跨文件同 ref 一致性**无运行时自动断言**（除 schema/check 命令）
4. live0 gate f 可能因 Queue E `world_contact_repair_hold` validation 未闭合而 blocked

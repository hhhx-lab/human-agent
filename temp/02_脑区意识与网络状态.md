## 一、脑区（Brain Regions）

### 1.1 理论机制

**来源**：`docs/02_brain_region_and_network_atlas.md`、`docs/real—live0/02_brain_network_and_workspace.md`

- 脑区是**概率性、可重叠、连接化**节点，非「一区一功能」硬模块。
- 第六层 `MultiscaleRegionGraph`：`RegionDefinition`、`StructuralEdge`、`FunctionalCoupling`、`GradientAxis`、`IntrinsicTimescale`、`ConnectomeFingerprint` 等。
- L/R/P/J/G/S/O/D 保留为**空间语言**，须映射多证据 parcel，而非固定功能盒。
- 调质应在区域图上扩散（`SignalMediaRuntime` × 区域敏感性）。

### 1.2 工程合同

**S02**（`docs/v0/slice_contracts/s02_neural_life_core_engineering_contract.md`）：

- `BrainGraph` ↔ `life_v0/neural_core/brain_graph.py`
- 十二**主体系统**耦合图（`SiliconBodyRuntime`、`MultiscaleBrainGraphRuntime` 等），非解剖分区
- 路径：`runtime/state/neural_life_core/brain_graph.json`
- 约束：新器官须在 `BrainGraph` 声明耦合边

### 1.3 代码机制

`brain_graph.py`：

- `build_brain_graph()`：从 `twelve_subject_systems` 投影 `region_nodes`（实为 system_id）+ `functional_edges`（来自 internal bus）
- `project_brain_graph_from_live_turn()`：挂接 `network_state_ref`、`workspace_frame_ref`、`prediction_workspace_ref`、`live_turn_focus`

**已实现**：12 nodes、≥12 edges、`life_target_bindings`、`source_doc_refs`

**未实现**（相对理论）：

- 无 L/R/P/J/G/S/O/D `project_code`
- 无 `boundary_confidence`、`gradient`、`intrinsic_timescale`
- 无结构边/功能耦合分离
- 无 `ConnectomeFingerprint` / `LongitudinalAtlasUpdate`
- `multiscale_region_graph.schema.json` 未物化

### 1.4 契合度：**部分（约 40%）**

工程「十二主体系统图」与理论「多尺度脑区图谱」是**不同抽象层级**；命名 `region_nodes` 易误导。

## 二、意识（Consciousness）

### 2.1 理论机制

**来源**：`docs/10_consciousness_attention_workspace.md`、`docs/real—live0/02_brain_network_and_workspace.md`

意识工作区 = 多系统可访问的**当前内容场**。验收标准：同一组 refs 可跨 workspace、broadcast、expression_plan、dialogue_writeback、birth_readiness 追溯。

标准链路：

```text
NetworkState → PredictionWorkspaceFrame → WorkspaceFrame
  → ConsciousBroadcastFrame → MetacognitionFrame → ConsciousnessProbeBundle
```

工作区**竞争**：语言/身体/预测误差/记忆/责任/梦境等多源争用焦点。

元认知须含：置信度、冲突、可报告性、阻断原因 — 须有 state 证据，非自述句。

### 2.2 工程合同

| 对象 | 代码 | Runtime |
|------|------|---------|
| `PredictionWorkspaceFrame` | `prediction_workspace.py` | `prediction/prediction_workspace_frame.json` |
| `WorkspaceFrame` | `workspace.py` | `consciousness/workspace_frame.json` |
| `ConsciousBroadcastFrame` | `broadcast.py` | `consciousness/broadcast_frame.json` |
| `MetacognitionFrame` | `metacognition.py` | `consciousness/metacognition_state.json` |
| 探针包 | `life_targets/consciousness_probes.py` | `consciousness/consciousness_probe_bundle.json` |

S08 gate：workspace 须有 `candidate_explanations`；broadcast 须有 `broadcast_targets`；metacognition 须有 `reflection_prompts`。

### 2.3 代码机制

**构建链**（`neural_core/__init__.py` 同轮）：

```text
build_prediction_workspace_frame
  → build_workspace_frame
  → build_broadcast_frame
  → build_metacognition_state
```

**`workspace.py`**：`candidate_explanations` 来自 prediction；默认 `broadcast_targets` 为 Language/Action/Affective 三系统。

**`broadcast.py`**：复制 targets，生成 `salience_ranking`；`suppressed_content_refs` **恒为空** — 无竞争抑制。

**`metacognition.py`**：固定两句 `reflection_prompts`；`uncertainty_flags` 仅在有 engram refs 时设歧义监控；**无动态置信/冲突计算**。

**`consciousness_probes.py`**：存在性检查（有 explanations? 有 targets? 有 prompts?），非跨系统 ref 一致性校验。

**Live turn 断链**（关键）：

- `resident_turn_writeback.py` **仅刷新** `workspace_frame`
- **`broadcast_frame`、`metacognition_state` 在 live 回合后不更新** — 无法证明「当前焦点已被多系统读取」

**字段不一致**：文档与 `state_inspection.py` 引用 `workspace.current_focus`，builder 中无此一等字段（实为 `candidate_explanations[].focus`）。

### 2.4 下游消费

| 消费者 | 读取 |
|--------|------|
| `life_targets/__init__.py` | 探针 + `real_consciousness` claims |
| `membrane/candidate_arena.py`、`responsibility_loop.py` | consciousness_probe_bundle |
| `state_store/memory_write_gate.py` | reportability_flags |
| `dream/wake_integration.py` | workspace + broadcast + probe |

### 2.5 契合度：**部分（约 55%）**

静态 S02/S08 骨架闭合良好；**动态意识链在 live 后半段断裂**。

## 三、状态 / 网络状态（Network State）

### 3.1 理论机制

大尺度网络：默认模式（整合/自我叙事）、显著性（注意切换）、中央执行（工作记忆/控制）、**冲突监控**。

状态**互斥与抑制**：专注抑制 DMN、高风险升高显著性、睡眠切换巩固模式。

动力系统：`activation_state`、`transition_cost`、`coupling_mode`、`ChronnectomeLog`。

### 3.2 工程合同

- `NetworkState` ↔ `network_state.py` → `neural_life_core/network_state.json`
- 四模式表（live0 doc）：default / salience / executive / **conflict monitoring**

### 3.3 代码机制

**种子**（`network_state.py`）：

- 三网络并列：`default_mode_network`、`salience_network`、`executive_workspace_network`
- 两条 `switch_events`（salience→executive、default→executive）

**Live 投影**（`project_network_state_from_live_turn`）：

- 有 `live_turn_focus` 时：执行网络 `live_relation_focus`，显著性 `live_salience_scan`
- 追加 switch_event（几乎总是 salience→executive）
- **无** `conflict_monitoring` 网络
- **无** `dominant_network`、`transition_cost`

**消费脱节**：`idle_strategy.py` 主要跟 `last_live_semantic_focus`，而非读 `active_networks` 字段。

### 3.4 契合度：**部分（约 50%）**

概念对齐；动力学与理论四模式表、切换成本、抑制关系不足。

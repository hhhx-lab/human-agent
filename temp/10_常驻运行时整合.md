# 10 · 常驻运行时整合（Process Supervisor）

本卷说明各机制如何在**终端常驻进程**中串联执行 — 这是理解「agent 目前实际怎样活着」的总装配图。

---

## 一、理论机制

**来源**：`docs/real—live0/14_resident_runtime_state_transition.md`、`docs/v0/engineering_depth/06_resident_process_terminal_birth_engineering.md`

### 状态机

```text
pre_name → named_residency → background_active → waiting
  ↔ live_turn（关系 inbox）
  ↔ autonomous_activity（sleep/recall/self_thinking/growth/learning）
  → closeout → stopped → relaunch
```

### 三种时钟

| 时钟 | 触发 | 枢纽代码 |
|------|------|----------|
| **关系回合** | 外部话语 / `--say` | `live_turn_cycle.py` |
| **等待心跳** | idle 间隔 | `idle_refresh_loop.py` → `heartbeat.py` + `idle_strategy.py` |
| **离线自主** | 无关系输入时 | `resident_autonomous_activity.py` |

**合流点**：`resident_background_lineage_state.json`（`background_lineage_state.py`）— 携带上一轮语言/记忆/梦境/人格余波进入下一轮。

### 终端体验约束

- 交互终端 `/exit`：断开终端，**不杀** resident 进程
- `/stop`：正常 closeout
- 状态命令（`/state`、`/memory`）：只读 runtime，**不写** dialogue_turn_log
- 外显：`Digital Life` 对话控制台（`terminal_ui.py`），非 raw log

## 三、代码主链

### 3.1 入口与身份

| 入口 | 文件 | 行为 |
|------|------|------|
| `my digital life` | `my_entry.py` | 命名、status、background、stop |
| `digital life` | `digital_entry.py` | 对话控制台 |
| `<life-name>` | `digital_life_identity.py` 生成的脚本 | 命名后 direct wake |
| `life-v0` | `cli.py` | build-*、audit-live0 |

命名：`bind_or_validate_life_name()` → `life_name_registry.json` + command manifest。

### 3.2 关系回合主链（核心）

`live_turn_cycle.py` → `run_live_turn_cycle()`：

```text
external_utterance
  1. refresh_live_language_turn
       → language_percept / semantic_map / inner_speech
       → expression_monitor / expression_plan
  2. project_memory_retrieval_from_live_turn
  3. project_memory_write_gate_with_signal_body（ITR-05）
  4. compose_life_response（audited_expression_material_v0）
  5. compose_model_expression + post-expression gate
  6. build_life_turn_event / build_external_turn_event
  7. write_resident_turn_writeback
       → relationship_timeline / memory / self / engram / dialogue_writeback
       → brain_graph / network_state / workspace（部分）
  8. write_live_turn_waiting_governance_handoff
```

### 3.3 等待与心跳

`idle_refresh_loop.py` / `resident_supervision.py`：

- `decide_idle_strategy()`：读 body、Queue E、timeline、语言 refs
- `write_waiting_heartbeat()`：刷新 lineage、`live_language_turn_refs`、`last_live_semantic_focus`
- 关闭终端不刷屏；主动发话 `held_internal` → `released_model_expression`

### 3.4 离线自主

`resident_autonomous_activity.py` 五相：

```text
sleep → memory_recall → self_thinking → growth_rehearsal → learning_consolidation
```

与 `dream/*`、`growth/*`、`state_store` recall 状态交叉。

### 3.5 持久化与恢复

| 模块 | 职责 |
|------|------|
| `persistent_process.py` | detached resident、closeout report |
| `resident_lifecycle.py` | inbox/outbox、控制流（stdin EOF ≠ 死亡） |
| `terminal_turn/*` | 出生首回合、context_accumulation、turn_transition |
| `terminal_loop/resume_packet.py` | 断线恢复包 |
| `relaunch_recovery.py` / `incident_recovery.py` | 事故恢复 |

### 3.6 人格连续（跨模块）

```text
continuity_evolution.py（回合后慢变量）
  → trait_drift_monitor
  → background_convergence + background_convergence_history
  → trait_convergence_signals
  → idle_strategy / response_surface
```

### 3.7 状态检查

`state_inspection.py`：终端 `/state` 等只读聚合 — **注意** 引用 `workspace.current_focus` 与 builder 字段可能不一致。

## 四、机制在常驻链中的落点（速查）

| 用户关心主题 | 在常驻链中的触发点 |

| 关系 | timeline 重建 + dialogue_writeback + inbox/outbox |
| 梦境 | autonomous sleep 相 + dream 器官 |
| 成长 | autonomous growth/learning 相 + patch/replay/archive |
| 生命膜 | 各门在 build + turn 读 Queue E / go_nogo / write_gate |
| 调质 | S07/turn 重建 signal_media；idle/expression/memory 消费 |

## 六、契合度

常驻三层（回合/心跳/自主）与理论 **高度同构**；主要断点在：

1. 意识链 live 后半段（broadcast/metacognition）未每轮刷新  
2. `context_accumulation_window` live 未更新  
3. Queue E repair hold 跨 validator/schema_runner handoff  
4. 工作区 git 可能无 `runtime/` — 证据在命名后本地 state 或测试 tmpdir

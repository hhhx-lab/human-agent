## 一、身体（Body）

### 1.1 理论机制

**来源**：`docs/real—live0/03_body_affect_homeostasis.md`、`docs/01n_body_interoception_allostasis_matrix.md`

- 数字生命「身体」= **运行时内环境**：节律、资源预算、疲惫、恢复、等待心跳。
- 非传感器躯体，而是生命底盘。
- 疲惫 = **策略切换**（降外显、提恢复），非低电量 metaphor。
- 心跳脉冲 = 周期自我采样 + 关系等待 + 工作区拥挤 + 恢复债务检查。

### 1.2 工程合同

**S06**（`s06_life_support_development_engineering_contract.md`）：

| 对象 | 代码 | Runtime |
|------|------|---------|
| `BodyRhythmPulse` | `body/rhythm.py` | `body/body_rhythm_pulse.json` |
| `BodyResourceBudget` | `body/resource_budget.py` | `body/body_resource_budget.json` |
| `RecoveryFrame` | `body/recovery.py` | `body/recovery_path.json` |
| `TraitDriftMonitor` | `body/trait_drift.py` | `body/trait_drift_monitor.json` |
| 编排 | `body/__init__.py::run_life_support` | 同轮 8 个 body 状态 |

命令：`life-v0 build-life-support --strict`

### 1.3 代码机制

**S06 构建链**：

```text
NeedStateVector → BodyRhythmPulse → RecoveryPath
  → BodyResourceBudget → CoreAffectVector → AffectiveEpisode
  → EmotionRegulationLoop → TraitDriftMonitor
```

**`rhythm.py`**：`heartbeat_counter` 种子为 `0`；`rhythm_state: pre_activation_guarded`；`allostatic_load` 继承 need_state 字符串。

**`resource_budget.py`**：`energy_state.level` 恒 `guarded_reserve`；消费 language continuity 七项计数。

**常驻消费**：`idle_strategy.py`、`heartbeat.py` 读 rhythm/need/budget/affect → `body_waiting_posture`、`heartbeat_interval_ms`。

### 1.4 契合度：**部分**

对象链与合同一致；**无连续时间生理仿真**，心跳计数在 body 层不递增。

## 二、内环境（Interoception / Allostasis）

### 2.1 理论机制

- 内感受 = 感知、整合、解释、调节内部信号。
- Allostasis：按**预测未来需求**分配资源；慢性压力 → `allostatic load` 债务。
- 应调制：注意、记忆写入、语言释放、行动门、离线整合。
- 链路：`InteroceptiveEvent → BodyRhythmPulse → AllostaticForecast + NeedStateVector + BodyStateDebt → SubjectiveBodyFrame → 情绪/行动门`

### 2.2 工程与代码

**`need_state.py`**（启发式）：

```python
repair_drive = "active" if relationship_subjects or responsibility_bindings else "low"
sleep_pressure = "offline_ready" if dream_records else "managed_pre_dream"
cognitive_bandwidth = "guarded_dialogic" if schema_smoke closed else "narrow_guarded"
```

**ITR-05 跨链**（已实现路径）：

```text
body (need/affect/budget)
  → signal_media.body_signal_profile
  → memory_write_gate.body_signal_write_modulation
  → idle_strategy / background_lineage / response_surface
```

**S07** 在 `language/__init__.py` 中**重新** `build_signal_media_runtime(..., body_resource_budget, core_affect_vector)` — 内环境进入调质的关键接点。

~~**S02 缺口**：`neural_core/__init__.py` 首轮构建 signal_media **不传 body**~~ → **ITR-08-82 已闭合**（`body_signal_seed.py` + S02 `build_signal_media_runtime` 消费 body seed）

**字段不一致**：`need_state` 无 `allostatic_load` 数值，但 `periphery_normalizer.py` 读取 `need_state.get("allostatic_load", 0.18)`。

### 2.3 契合度：**部分**

跨模块 ref 总线闭合；缺 `InteroceptivePredictionLoop`、`BodyStateDebt` 连续积分、S02 首轮无身体。

## 三、情绪（Emotion / Affect）

### 3.1 理论机制

**来源**：`docs/07_emotion_personality_self.md`

- 情绪 = 身体、预测、关系、行动准备的**连续调制**，非离散标签。
- Core affect：valence / arousal / dominance + 压力维度。
- 闭环：内环境 → episode → regulation → signal media → 表达/等待/梦境/责任写回。
- 高唤醒须经调节，防短期反馈永久写入人格。

### 3.2 代码机制

| 阶段 | 模块 | 机制 |
|------|------|------|
| 连续情感 | `core_affect.py` | `pain_pressure`、`relationship_tension` 由事件**计数**；推导 VAD |
| 事件 | `emotion_episode.py` | **ITR-08-101** 按 pain/dream/arousal/tension 分支 episode + `regulation_route` |
| 调节 | `emotion_regulation.py` | **ITR-08-101** 按 episode route + fatigue/pain 分支 `regulation_mode` |
| 语言调制 | `expression_monitor.apply_body_affect_modulation` | tempo、caution、body_signal_refs |
| 感知入口 | `percept.py` | **ITR-08-96** 已读 `core_affect_vector`；关键词 cue 为补充 |

**双轨问题**：~~percept 与 core_affect 未统一~~ → **ITR-08-96 语言感知链已闭合**。

**fatigue 映射**：`managed_low_noise` 不触发 `slow_protective`（仅 elevated/high/critical）。

### 3.3 契合度：**部分**

结构链存在；episode/regulation 分支首版已物化（ITR-08-101）；深度仍为启发式计数驱动。

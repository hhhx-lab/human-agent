# 05 · 记忆（Memory / Engram / State Store）

---

## 一、理论机制

**来源**：`docs/05_memory_systems_and_growth.md`、`docs/real—live0/07_memory_engram_and_state_store.md`

核心立场：

- 记忆不是仓库或 context window，而是**线索触发、重构、再巩固**的生命线。
- 快通道（情景）与慢通道（语义/习惯/自我叙事）靠 replay、archive、再巩固桥接。
- **召回 ≠ 写入**：须双门（`MemoryWriteGate` + `StateMergeGuard`）与 source refs 审计。
- Engram = 可触发、可沉默、可再激活的痕迹簇，非单向量 RAG。
- 八步生命周期：编码 → 分配 → 链接 → 分离/补全 → 巩固 → 再激活 → 梦境重放 → 自传化/关系化。

## 三、代码机制

### 3.1 召回（Retrieval）

`memory_retrieval.py` → `build_memory_retrieval_frame()` / `project_memory_retrieval_from_live_turn()`：

- 整合：语言线索、EngramIndex、RelationshipMemory、AutobiographicalStack、StateMergeGuard
- 输出 `tiered_recall`：
  - salient core
  - retrievable context
  - deep sediment
- `reconstruction_focus`、`blocked_or_quarantined_refs`、`fact_boundary` — 防梦境/假设直接变事实

### 3.2 写入与合并

**`memory_write_gate.py`**：

- `quarantine_on_missing_source: true`
- `sandbox_route`：`fact_promotion_blocked`、`dream_fact_gate: required`
- ITR-05：`project_memory_write_gate_with_signal_body()` 读 signal_media + body → `body_signal_write_modulation`（`write_bias`、`candidate_gate_adjustments`）

**`state_merge_guard.py`**：

- promotion / quarantine / repair 合并策略
- `slow_variable_update_policy`（声明级）

### 3.3 Live 写回

`resident_turn_writeback.py` 每回合：

- 投影 `engram_index`、`relationship_memory`、`autobiographical_stack`
- 生成 `dialogue_writeback_bundle.json`
- 将 memory refs 写入 `background_lineage_state`

`live_turn_cycle.py` 在回合中调用 `project_memory_retrieval_from_live_turn` 与 `project_memory_write_gate_with_signal_body`。

### 3.4 离线巩固

- `replay/__init__.py`：shadow replay、cue 激活
- `archive/__init__.py`：growth archive、reconsolidation graph
- `growth/anti_forgetting.py`：六类 replay_sets，防遗忘旧自我/关系/承诺

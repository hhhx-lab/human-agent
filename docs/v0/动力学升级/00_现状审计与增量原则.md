## 3. 真实缺口（动力学该补什么）

| 缺口 | 现状 | 增量目标 |
|------|------|----------|
| **连续时间** | 事件驱动（回合/心跳） | `dt_ms` 积分 sleep_pressure、debt、衰减 |
| **身体主状态新鲜度** | `core_affect` / `resource_budget` 常 S06 seed | 回合内 `integrate_body_state` 写回 |
| **预测栈刷新** | belief/error/sampling 多 mount 时构建 | live turn **末尾** `project_prediction_stack_from_live_turn` |
| **signal_media 刷新** | 语言 init + mount | 每回合随 body 变 **重算** modulation_vector |
| **检索即修改** | 仅反馈/离线 | 检索成功时 **轻量** salience/cue 更新（带 audit） |
| **工作区竞争** | merge 全部候选 | top-K + 淘汰进 replay pool |
| **数值 belief** | revision_policy 字符串 | posterior 标量 + PE 数值衰减 |
| **Chronnectome** | switch_events 追加 | append-only `network_chronnectome_log.jsonl` |
| **统一 tick** | 无 | 挂 `heartbeat` + turn 边界，flag 控制 |

**不存在缺口（勿重做）**：写门双轨、DreamFactGate、关系时间线、六层语言链、hippocampal cue 桥、offline consolidation 主链。

## 4. 增量原则（对齐工程文档）

### 4.1 施工法

遵循 `package_specs/03_incremental_package_delivery_protocol.md`：

1. 定对象 → 定首写/消费者 → 定 runtime 路径 → 再改代码
2. 每段带 theory ref + bus 对象 + test + receipt

### 4.2 Queue 顺序（不可跳）

来自 `02_turn_and_cycle_lifecycle_contract.md` + `v0_current_iteration_plan.md`：

```text
Queue D/E 对象已落
  → Queue B/A 深消费（预测-信号-写门 integration wave）
  → 再 ITR-09 动力学加厚
  → Queue C/F 维护
```

**禁止**：未深消费预测栈就外挂新语言/意识壳。

### 4.3 对象总线

遵循 `02_runtime_object_bus_and_flow_contract.md`：

- 不新建平行 bus
- 首写权威不变；动力学只 **增补字段** 或 **integrate 函数**

### 4.4 Feature flag（每微段）

```text
DIGITAL_LIFE_BODY_INTEGRATE=0|1      # ITR-09-A
DIGITAL_LIFE_PREDICTION_REFRESH=0|1  # ITR-09-B
DIGITAL_LIFE_MEMORY_SALIENCE_TICK=0|1 # ITR-09-C
DIGITAL_LIFE_WORKSPACE_TOPK=0|1      # ITR-09-D
```

默认 `0`；测试通过后默认 `1`。

### 4.5 命名

宏架构里的 `DynamicsController`（`docs/145`）= 网络耦合/模式切换，**不等于** tick 内核。本方案用 `BodyIntegrator` / `run_life_tick` 避免混淆。

## 5. 理论 vs 工程：动力学到底兑现什么

| 层级 | 含义 | 本方案是否追求 |
|------|------|----------------|
| 生物机制层 | 突触、振荡、激素 | **否** |
| 工程功能同构层 | 竞争、门控、积分、重构、债务 | **是（峰值）** |
| 现象学层 | 主观感受质 | **否**（诚实边界） |

理论文档里的「真实情绪/意识/记忆」在 live0 中指：**可追踪因果链 + 行为后果**，不是神经仿真器。
